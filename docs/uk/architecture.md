# Архітектура

[README](../../README.uk.md) | [English](../architecture.md)

Проєкт організований за функціональними підсистемами. Є спільні моделі даних, брокерні інтерфейси, окремі компоненти replay, backtest, зберігання та діагностики. Частина відповідальності залишається у великих центральних компонентах.

## Концептуальний потік

```text
Ринкові дані → метрики та патерни → торговий сценарій
                                      ↓
                        правила стратегії / ML-рішення
                                      ↓
                       перевірки ризику та виконання
                                      ↓
                            журнали й звіти

Записані події → replay / backtest → порівняння та дослідження
Поточні події  → shadow-стратегії → альтернативні результати
```

Це огляд ролей компонентів, а не точна схема всіх викликів. Не кожна стратегія використовує ML, а місце конкретного ML-рішення залежить від його задачі.

## Розподіл відповідальності

| Компоненти | Роль |
|---|---|
| UI та engine | Збір даних, відображення, розрахунки й обробка сигналів |
| domain, features, signals | Події, ознаки та формування сигналів |
| algo | Координація стратегій, AI-сервісів і виконання |
| trading | Брокерні адаптери, облік, нормалізація ордерів і ризики |
| replay, backtest | Відтворення та програвання стратегій |
| storage, audit | Збереження та аудит подій |
| tools | Навчання, оцінювання, експорт і діагностика |

Організація роботи AI-агентів доповнює цей поділ: окремі спеціалізовані чати отримують спільний контекст і локальні задачі. Чати не є Git-гілками або незалежними сервісами.
